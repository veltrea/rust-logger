# Руководство пользователя rust-logger

`rust-logger` — это инструмент, который воспроизводит функциональность стандартной команды UNIX `logger` в Windows с расширенной поддержкой японской среды. Он используется для отправки сообщений на сервер Syslog из различных скриптов и приложений в Windows.

---

## 1. Что такое Syslog?
Syslog — это стандартный протокол для пересылки лог-сообщений по сети.
Обычно он включает в себя комбинацию инструмента отправителя (например, `rust-logger`) и сервера получателя/хранилища (например, `vlt-syslogd`).

### Компоненты сообщения
В дополнение к основному тексту сообщение Syslog включает следующую информацию:
- **Приоритет (Priority)**: Важность сообщения. Указывается как `facility.level` (например: `user.info`).
- **Тег (Tag)**: Идентификатор, указывающий, какое приложение сгенерировало лог (например: `web-server`).
- **Временная метка (Timestamp)**: Дата и время генерации лога.
- **Имя хоста (Hostname)**: Имя машины, отправившей лог.

---

## 2. Основное использование
Вы можете отправить сообщение, просто добавив его в конец командной строки.

### Минимальное выполнение
```cmd
rust-logger -n 127.0.0.1 "Тестовое сообщение"
```

### Примеры использования приоритета (-p)
Важно указать соответствующий приоритет в зависимости от ситуации, чтобы включить эффективную фильтрацию и настройки уведомлений на стороне сервера Syslog.

| Ситуация | Рекомендуемый пример команды | Намерение |
| :--- | :--- | :--- |
| **Запись нормальной операции** | `-p user.info` | Нормальные записи, такие как "...начато" или "...завершено". |
| **Требует внимания** | `-p user.warning` | "Произошла повторная попытка", "Мало места на HDD" и т. д. |
| **Незначительная ошибка** | `-p user.err` | Сбои, такие как "Не удалось обработать некоторые файлы". |
| **Критическая ошибка** | `-p user.crit` | Фатальные ситуации, такие как "Невозможно подключиться к базе данных". |
| **Важное уведомление** | `-p user.notice` | Важные записи, не являющиеся ошибками, такие как "Конфигурация изменена". |
| **Вывод отладки** | `-p user.debug` | Подробный вывод, такой как содержимое переменных во время разработки скрипта. |

### Часто используемые опции
- `-n [Имя сервера]`: Сервер назначения (Обязательно).
- `-p [Приоритет]`: `user.notice`, `local0.err` и т. д. (По умолчанию: `user.info`).
- `-t [Тег]`: Имя приложения и т. д. (По умолчанию: `rust-logger`).

## 3. Практические примеры

### Использование в пакетных файлах (.bat)
Полезно для уведомлений при запуске/окончании скрипта или при возникновении ошибки.
```batch
@echo off
set SERVER=192.0.2.10
rust-logger -n %SERVER% -t "BackupScript" "Запуск процесса резервного копирования"

copy C:\data D:\backup
if %ERRORLEVEL% NEQ 0 (
    rust-logger -n %SERVER% -p local0.err -t "BackupScript" "Ошибка: Резервное копирование не удалось"
) else (
    rust-logger -n %SERVER% -t "BackupScript" "Резервное копирование завершено"
)
```

### Использование в PowerShell (.ps1)
В PowerShell рекомендуется вставлять «Контрмеру против Модзибаке» (Mojibake), описанную ниже, в начало скрипта.
```powershell
$Logger = "rust-logger.exe"
$Server = "127.0.0.1"

# Контрмера против Модзибаке (Обязательно)
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

& $Logger -n $Server -t "PS-Script" "Тестовое уведомление от PowerShell"
```

## 4. Устранение неполадок: исправление Модзибаке (искаженного текста)

При работе с японским языком (или многобайтовыми символами) в Windows обратите внимание на следующие моменты.

### Если Модзибаке происходит в PowerShell
PowerShell 5.1 имеет тенденцию вызывать искажение символов при передаче аргументов внешним командам.
1.  Сохраните скрипт как **UTF-8 with BOM**.
2.  Явно установите кодировку внутри скрипта (см. пример PowerShell выше).

### Если Модзибаке происходит в командной строке
`rust-logger` автоматически определяет и обрабатывает ввод, даже если это Shift-JIS (CP932), но если отображение нарушено, временно измените кодовую страницу на UTF-8.
```cmd
chcp 65001
```

### Если Модзибаке происходит на стороне назначения
Если целевой сервер Syslog ожидает определенную кодировку (например, Shift-JIS), используйте опцию `--encoding`.
```cmd
rust-logger -n 127.0.0.1 --encoding shift_jis "Японское сообщение"
```

## 5. Справочник по приоритетам (Level и Facility)

| Уровень (Severity) | Описание |
| :--- | :--- |
| `emerg`, `panic` | Система непригодна для использования (наивысший приоритет) |
| `alert` | Необходимо принять меры немедленно |
| `crit` | Критические состояния |
| `err`, `error` | Состояния ошибки |
| `warning`, `warn` | Состояния предупреждения |
| `notice` | Нормальное, но значимое состояние |
| `info` | Информационные сообщения |
| `debug` | Сообщения уровня отладки |
