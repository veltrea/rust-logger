# rust-logger उपयोगकर्ता नियमावली (User Manual)

`rust-logger` एक ऐसा टूल है जो विंडोज़ (Windows) पर UNIX मानक `logger` कमांड की कार्यक्षमता को फिर से बनाता है, और जापानी भाषा के वातावरण के लिए बेहतर समर्थन प्रदान करता है। इसका उपयोग विंडोज़ पर विभिन्न स्क्रिप्ट और एप्लिकेशन से Syslog सर्वर पर संदेश भेजने के लिए किया जाता है।

---

## 1. Syslog क्या है?
Syslog नेटवर्क पर लॉग संदेशों को अग्रेषित (forward) करने के लिए एक मानक प्रोटोकॉल है।
आमतौर पर, इसमें एक भेजने वाले टूल (जैसे `rust-logger`) और एक प्राप्त करने/स्टोर करने वाले सर्वर (जैसे `vlt-syslogd`) का संयोजन शामिल होता है।

### संदेश के घटक (Components)
मुख्य पाठ के अलावा, एक Syslog संदेश में निम्नलिखित जानकारी शामिल होती है:
- **प्राथमिकता (Priority)**: संदेश का महत्व। इसे `facility.level` (उदा: `user.info`) के रूप में निर्दिष्ट किया जाता है।
- **टैग (Tag)**: एक पहचानकर्ता जो बताता है कि किस एप्लिकेशन ने लॉग जेनरेट किया (उदा: `web-server`)।
- **टाइमस्टैम्प (Timestamp)**: लॉग जेनरेट होने की तारीख और समय।
- **होस्टनाम (Hostname)**: उस मशीन का नाम जिसने लॉग भेजा।

## 2. मूल उपयोग (Basic Usage)
आप बस कमांड लाइन के अंत में संदेश जोड़कर इसे भेज सकते हैं।

### न्यूनतम निष्पादन (Minimal Execution)
```cmd
rust-logger -n 127.0.0.1 "परीक्षण संदेश"
```

### प्राथमिकता (-p) का उपयोग करने के उदाहरण
स्थिति के अनुसार उचित प्राथमिकता निर्दिष्ट करना महत्वपूर्ण है ताकि Syslog सर्वर की तरफ प्रभावी फ़िल्टरिंग और नोटिफिकेशन सेटिंग सक्षम हो सके।

| स्थिति | अनुशंसित कमांड उदाहरण | उद्देश्य |
| :--- | :--- | :--- |
| **सामान्य संचालन रिकॉर्ड** | `-p user.info` | सामान्य रिकॉर्ड जैसे "...शुरू हुआ" या "...पूरा हुआ"। |
| **ध्यान देने योग्य** | `-p user.warning` | "पुनः प्रयास हुआ", "HDD स्पेस कम है", आदि। |
| **मामूली त्रुटि** | `-p user.err` | विफलताएं जैसे "कुछ फ़ाइलों को संसाधित नहीं किया जा सका"। |
| **गंभीर त्रुटि** | `-p user.crit` | घातक स्थितियां जैसे "डेटाबेस से कनेक्ट नहीं किया जा सकता"। |
| **महत्वपूर्ण सूचना** | `-p user.notice` | महत्वपूर्ण रिकॉर्ड जो त्रुटि नहीं हैं, जैसे "कॉन्फ़िगरेशन बदला गया"। |
| **डिबग आउटपुट** | `-p user.debug` | स्क्रिप्ट विकास के दौरान विस्तृत आउटपुट जैसे वेरिएबल की सामग्री। |

### सामान्य विकल्प
- `-n [सर्वर नाम]`: गंतव्य सर्वर (आवश्यक)।
- `-p [प्राथमिकता]`: `user.notice`, `local0.err`, आदि (डिफ़ॉल्ट: `user.info`)।
- `-t [टैग]`: एप्लिकेशन का नाम, आदि (डिफ़ॉल्ट: `rust-logger`)।

## 3. व्यावहारिक उदाहरण (Practical Examples)

### बैच फ़ाइलों (.bat) में उपयोग
स्क्रिप्ट शुरू/समाप्त होने पर या त्रुटि होने पर नोटिफिकेशन के लिए उपयोगी।
```batch
@echo off
set SERVER=192.0.2.10
rust-logger -n %SERVER% -t "BackupScript" "बैकअप प्रक्रिया शुरू हो रही है"

copy C:\data D:\backup
if %ERRORLEVEL% NEQ 0 (
    rust-logger -n %SERVER% -p local0.err -t "BackupScript" "त्रुटि: बैकअप विफल रहा"
) else (
    rust-logger -n %SERVER% -t "BackupScript" "बैकअप पूरा हुआ"
)
```

### PowerShell (.ps1) में उपयोग
PowerShell में, नीचे वर्णित "मोजिबेक (Mojibake) उपाय" को स्क्रिप्ट की शुरुआत में डालने की अनुशंसा की जाती है।
```powershell
$Logger = "rust-logger.exe"
$Server = "127.0.0.1"

# मोजिबेक उपाय (आवश्यक)
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

& $Logger -n $Server -t "PS-Script" "PowerShell से परीक्षण सूचना"
```

## 4. समस्या निवारण: मोजिबेक (गड़बड़ टेक्स्ट) को ठीक करना

विंडोज़ पर जापानी (या मल्टी-बाइट वर्णों) को संभालते समय, कृपया निम्नलिखित बिंदुओं पर ध्यान दें।

### यदि PowerShell में मोजिबेक होता है
PowerShell 5.1 बाहरी कमांड को तर्क (arguments) पास करते समय अक्सर टेक्स्ट को गड़बड़ कर देता है।
1.  स्क्रिप्ट को **UTF-8 with BOM** के साथ सहेजें।
2.  स्क्रिप्ट के भीतर एन्कोडिंग को स्पष्ट रूप से सेट करें (ऊपर PowerShell उदाहरण देखें)।

### यदि कमांड प्रॉम्प्ट में मोजिबेक होता है
`rust-logger` स्वचालित रूप से इनपुट को निर्धारित और संसाधित करता है, भले ही वह Shift-JIS (CP932) हो, लेकिन यदि डिस्प्ले खराब है, तो अस्थायी रूप से कोड पेज को UTF-8 में बदलें।
```cmd
chcp 65001
```

### यदि गंतव्य पर मोजिबेक होता है
यदि गंतव्य Syslog सर्वर एक विशिष्ट एन्कोडिंग (जैसे Shift-JIS) की अपेक्षा करता है, तो `--encoding` विकल्प का उपयोग करें।
```cmd
rust-logger -n 127.0.0.1 --encoding shift_jis "जापानी संदेश"
```

## 5. प्राथमिकता (Level और Facility) संदर्भ

| स्तर (Severity) | विवरण |
| :--- | :--- |
| `emerg`, `panic` | सिस्टम अनुपयोगी है (सर्वोच्च प्राथमिकता) |
| `alert` | कार्रवाई तुरंत की जानी चाहिए |
| `crit` | गंभीर स्थितियां |
| `err`, `error` | त्रुटि स्थितियां |
| `warning`, `warn` | चेतावनी स्थितियां |
| `notice` | सामान्य लेकिन महत्वपूर्ण स्थिति |
| `info` | सूचनात्मक संदेश |
| `debug` | डिबग-स्तर के संदेश |
