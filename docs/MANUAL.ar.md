# دليل مستخدم rust-logger

`rust-logger` هي أداة تعيد إنتاج وظائف أمر UNIX القياسي `logger` على نظام Windows، مع دعم معزز لبيئة اللغة اليابانية. يتم استخدامه لإرسال الرسائل إلى خادم Syslog من نصوص برمجية وتطبيقات مختلفة على Windows.

---

## 1. ما هو Syslog؟
Syslog هو بروتوكول قياسي لإعادة توجيه رسائل السجل عبر الشبكة.
عادةً ما يتضمن مزيجًا من أداة مرسل (مثل `rust-logger`) وخادم مستقبل/تخزين (مثل `vlt-syslogd`).

### مكونات الرسالة
بالإضافة إلى النص الأساسي، تتضمن رسالة Syslog المعلومات التالية:
- **الأولوية (Priority)**: أهمية الرسالة. تحدد كـ `facility.level` (مثال: `user.info`).
- **العلامة (Tag)**: معرف يشير إلى التطبيق الذي أنشأ السجل (مثال: `web-server`).
- **الطابع الزمني (Timestamp)**: تاريخ ووقت إنشاء السجل.
- **اسم المضيف (Hostname)**: اسم الجهاز الذي أرسل السجل.

---

## 2. الاستخدام الأساسي
يمكنك إرسال رسالة ببساطة عن طريق إضافتها إلى نهاية سطر الأوامر.

### التنفيذ البسيط
```cmd
rust-logger -n 127.0.0.1 "رسالة اختبار"
```

### أمثلة على استخدام الأولوية (-p)
من المهم تحديد الأولوية المناسبة وفقًا للموقف لتمكين إعدادات التصفية والإشعارات الفعالة على جانب خادم Syslog.

| الموقف | أمر موصى به (مثال) | القصد |
| :--- | :--- | :--- |
| **سجل التشغيل العادي** | `-p user.info` | سجلات عادية مثل "تم بدء..." أو "تم الانتهاء من...". |
| **يستدعي الانتباه** | `-p user.warning` | "حدثت إعادة محاولة"، "مساحة القرص الصلب منخفضة"، وما إلى ذلك. |
| **خطأ بسيط** | `-p user.err` | إخفاقات مثل "تعذرت معالجة بعض الملفات". |
| **خطأ فادح** | `-p user.crit` | حالات قاتلة مثل "لا يمكن الاتصال بقاعدة البيانات". |
| **إشعار هام** | `-p user.notice` | سجلات مهمة ليست أخطاء، مثل "تم تغيير التكوين". |
| **مخرجات التصحيح** | `-p user.debug` | مخرجات مفصلة مثل محتويات المتغير أثناء تطوير النص البرمجي. |

### الخيارات الشائعة
- `-n [اسم الخادم]`: الخادم الوجهة (مطلوب).
- `-p [الأولوية]`: `user.notice`, `local0.err`, وما إلى ذلك (الافتراضي: `user.info`).
- `-t [العلامة]`: اسم التطبيق، وما إلى ذلك (الافتراضي: `rust-logger`).

## 3. أمثلة عملية

### الاستخدام في ملفات الدفعات (.bat)
مفيد للإشعارات عند بدء/انتهاء النص البرمجي أو عند حدوث خطأ.
```batch
@echo off
set SERVER=192.0.2.10
rust-logger -n %SERVER% -t "BackupScript" "بدء عملية النسخ الاحتياطي"

copy C:\data D:\backup
if %ERRORLEVEL% NEQ 0 (
    rust-logger -n %SERVER% -p local0.err -t "BackupScript" "خطأ: فشل النسخ الاحتياطي"
) else (
    rust-logger -n %SERVER% -t "BackupScript" "اكتمل النسخ الاحتياطي"
)
```

### الاستخدام في PowerShell (.ps1)
في PowerShell، يوصى بإدراج "إجراء مضاد لـ Mojibake" الموضح أدناه في بداية النص البرمجي.
```powershell
$Logger = "rust-logger.exe"
$Server = "127.0.0.1"

# إجراء مضاد لـ Mojibake (مطلوب)
$OutputEncoding = [System.Text.Encoding]::UTF8
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8

& $Logger -n $Server -t "PS-Script" "إشعار اختبار من PowerShell"
```

## 4. استكشاف الأخطاء وإصلاحها: حل Mojibake (نص مشوه)

عند التعامل مع اللغة اليابانية (أو الأحرف متعددة البايت) على Windows، يرجى ملاحظة النقاط التالية.

### إذا حدث Mojibake في PowerShell
يميل PowerShell 5.1 إلى التسبب في تشوه الأحرف عند تمرير الوسيطات إلى الأوامر الخارجية.
1.  احفظ النص البرمجي بترميز **UTF-8 with BOM**.
2.  عين الترميز صراحة داخل النص البرمجي (انظر مثال PowerShell أعلاه).

### إذا حدث Mojibake في موجه الأوامر
يحدد `rust-logger` المدخلات ويعالجها تلقائيًا حتى لو كانت Shift-JIS (CP932)، ولكن إذا كانت الشاشة مشوشة، فقم بتغيير صفحة الكود مؤقتًا إلى UTF-8.
```cmd
chcp 65001
```

### إذا حدث Mojibake في الوجهة
إذا كان خادم Syslog الوجهة يتوقع ترميزًا معينًا (مثل Shift-JIS)، فاستخدم الخيار `--encoding`.
```cmd
rust-logger -n 127.0.0.1 --encoding shift_jis "رسالة يابانية"
```

## 5. مرجع الأولوية (Level و Facility)

| المستوى (Severity) | الوصف |
| :--- | :--- |
| `emerg`, `panic` | النظام غير قابل للاستخدام (أعلى أولوية) |
| `alert` | يجب اتخاذ إجراء فورًا |
| `crit` | حالات حرجة |
| `err`, `error` | حالات خطأ |
| `warning`, `warn` | حالات تحذير |
| `notice` | حالة طبيعية ولكنها هامة |
| `info` | رسائل معلوماتية |
| `debug` | رسائل مستوى التصحيح |
